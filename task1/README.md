# Задание 1. Исследование моделей и инфраструктуры

## Контекст
В качестве источника данных выступает база знаний с внутренней документацией. База знаний растёт, но плохо структурирована и слабо покрывает реальные запросы. Одни и те же процессы описаны в Confluence, Notion и PDF-регламентах, но расходятся по версиям. 

Статистика:
- ≈ 18 000 Markdown/MDX файлов в репозиториях.
- ≈ 3 000 страниц Confluence (30 пространств).
- ≈ 250 PDF‑спецификаций (наследие заказных проектов).
- Объём прироста — примерно 400 страниц в месяц.

### Подробно

#### Качество ответов

* **Локальные модели:**
    - **Llama 3 70B** - высокое качество ответов на технические вопросы, хорошие способности к логическому анализу и работе со сложной документацией. Оптимальный выбор для обработки больших объемов структурированной и неструктурированной информации.
    - **Mixtral 8x22B** - обеспечивает высокое качество генерации при относительно меньших вычислительных затратах. Эффективно работает с многоязычным контентом, включая русскоязычные технические тексты.
    - **Qwen 72B** - хорошая поддержка русского языка

* **Облачные модели:**
    - **OpenAI** - Качество ответов высокое и предсказуемое. Хорошо подходит для обработки структурированных текстов (технические спецификации, документы с форматированием).
    - **YandexGPT** - хороший вариант для **русскоязычной внутренней документации**, особенно если требуется хранение и обработка данных **в юрисдикции РФ**. Работа с русскими текстами с более корректной морфологией и стилистикой.

#### Скорость работы

* **Локальные модели:**
    - Минимальная задержка после загрузки модели в память (нет сетевых задержек).
    - Скорость генерации зависит от оборудования. На GPU - высокая, на CPU или слабом GPU - заметные задержки.
    - Время загрузки: Модель требуется загружать в память, что занимает время.

* **Облачные модели:**
    - Задержка: Стабильные отклики API (~1-3 секунды для простых запросов, 5-15+ секунд для сложных с большим контекстом).
    - Скорость генерации: Высокая, обеспечивается инфраструктурой провайдера.
    - Зависимость: Скорость зависит от интернет-соединения и нагрузки на API.

#### Стоимость владения

* **Локальные модели:**
    - Высокие первоначальные затраты на инфраструктуру (GPU, серверы).
    - Низкие эксплуатационные расходы (электричество, охлаждение).
    - Неограниченное количество экспериментов без дополнительной оплаты.
    - Выгодно при больших объемах запросов в долгосрочной перспективе.

* **Облачные модели:**
    - Простая структура затрат, но риск быстрого роста расходов при увеличении нагрузки.
    - Оплата по токенам/API-вызовам.
        - GPT-5: ~$1.25/1M токенов (вход) + $10/1M токенов (выход)
        - GPT-4: ~$3/1M токенов (вход) + $12/1M токенов (выход)

#### Удобство и простота развёртывания

* **Локальные модели:**
    - **Сложность использования**: Высокая - требуются технические знания для настройки, оптимизации и обслуживания.
    - **Инфраструктура**: Полная ответственность за работоспособность и мониторинг.
    - **Гибкость**: Полный контроль над средой выполнения, возможность тонкой настройки и дообучения моделей.
    - **Безопасность**: Гарантированная конфиденциальность данных, обработка внутри инфраструктуры.

* **Облачные модели:**
    - **Сложность использования**: Низкая - получение API-ключа, подключение SDK.
    - **Инфраструктура**: Полное обслуживание на стороне провайдера.
    - **Ограничения**: Невозможность тонкой настройки модели, работа в рамках API-ограничений.
    - **Безопасность**: Данные передаются третьей стороне, что может нарушать политики конфиденциальности.

## Резюме

*   **LLM (Модель для генерации ответов):** **Локальная `Llama 3.1 70B` (4-bit) + облачный `YandexGPT` как fallback**. Это обеспечивает баланс между качеством, контролем над данными и стоимостью. Локальная модель обрабатывает большинство запросов, а YandexGPT страхует на пиковых нагрузках и для задач, критичных к качеству русского языка, с соблюдением требований к хранению данных в РФ.
* Для разработки и тестирования можно использовать `llama3.2:3b` т.к. она гораздо менее требовательна к ресурсам.
*   **Эмбеддинги (Векторизатор текста):** **Локальная `intfloat/multilingual-e5-base`**. Решение с нулевой стоимостью использования, отличным качеством и полной безопасностью, что критично для внутренней документации. Облачные варианты не рассматриваются из-за рисков передачи конфиденциальных данных.
*   **Векторная БД:** **FAISS**. Выбор обусловлен максимальной скоростью поиска и индексации, что ключево для отзывчивости RAG-системы. Простота интеграции и низкая задержка делают его идеальным для старта и работы в продакшене.
*   **Инфраструктура:** **Оптимальная конфигурация сервера** (2x Xeon Silver 4316, 256 ГБ RAM, 2x RTX 4090). Это надежная основа для обработки 100-500 пользователей, обеспечивающая высокую производительность для локальных моделей и возможность параллельного инференса. Гибридный подход с облаком дает запас по масштабируемости.
